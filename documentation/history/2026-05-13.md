## SOURCE CODE — errors

### `graph-canvas.ts:40` — two stacked errors

The line `// eslint-disable-next-line @typescript-eslint/no-explicit-any` followed by `private graph: any = null` triggered both:

- **Unexpected undescribed directive comment** (the disable lacks a `-- reason` suffix).
- **Disabling `@typescript-eslint/no-explicit-any` is not allowed** (this disable is an _error_, not a warning — the rule cannot be suppressed even with a description).

Removed the disable and gave `graph` a real type from `force-graph`:

```ts
private graph: ForceGraph<GraphNode, GraphLink> | null = null
```

That single change cleared all 26+ cascade warnings (`Unsafe call`, `Unsafe member access ._destructor / .d3ReheatSimulation / .d3Force / .strength / .distanceMax / .distance / .width / .height / .graphData / .zoomToFit / .zoom / .centerAt`, `Unsafe assignment`) because the typed class already declares every method we use.

One subtlety: `force-graph`'s `d3Force()` returns `ForceFn<N> | undefined` whose body is `[key: string]: any`, so naive access to `.strength` / `.distance` / `.distanceMax` would have reintroduced unsafe-any. Defined three minimal local interfaces (`ChargeForce`, `LinkForce`, `CenterForce`) and cast `d3Force(...)` to them — avoids pulling `@types/d3-force` into the dep tree and lets us drop the `typeof charge.strength === 'function'` guards (the cast already narrows to the right shape).

Also dropped two now-redundant `as number` / `as { x: number; y: number }` casts in `getViewportState()` — `zoom()` and `centerAt()` are already typed.

### Timers + RAF → `window.*`

Per the obsidianmd rule, timer functions want `window.X(...)` (**not** `activeWindow.X(...)` — that one's also flagged). Swept across 5 files:

- `setTimeout` × 7 (`graph-canvas.ts` × 2, `graph-context-menu.ts` × 1, `graph-controls.ts` × 3, `graph-side-panel.ts` × 1).
- `clearTimeout` × 3 (`graph-canvas.ts`).
- `requestAnimationFrame` × 3 (`graph-context-menu.ts` × 1, `graph-minimap.ts` × 2).
- `cancelAnimationFrame` × 1 (`graph-minimap.ts`) — not flagged but swept for consistency (it pairs with the RAFs that were flagged).

Also retyped `private zoomTimer: ReturnType<typeof setTimeout> | null = null` to plain `number | null` — with `@types/bun` in scope, `setTimeout` is overloaded to return Bun's `Timer` (Node-style), but `window.setTimeout` returns `number` (DOM), so the assignment fails otherwise.
