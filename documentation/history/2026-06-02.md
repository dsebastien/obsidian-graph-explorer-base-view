# 2026-06-02 — Fix #1: Tailwind Preflight leaks globally and breaks other plugins

## Issue

GitHub issue [#1](https://github.com/dsebastien/obsidian-graph-explorer-base-view/issues/1): with only this plugin and the Datepicker plugin installed, the datepicker's date-input visuals are broken (extra blank space below, missing controls). Reported on Obsidian 1.12.7 / Windows / default theme.

## Root cause

`src/styles.src.css` started with `@import 'tailwindcss';`. In Tailwind v4 that shorthand expands to:

```css
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/preflight.css' layer(base);
@import 'tailwindcss/utilities.css' layer(utilities);
```

The `base` layer is **Preflight** — Tailwind's global CSS reset. It targets bare element selectors (`input`, `button`, `select`, `textarea`, `ul`, `ol`, `h1`–`h6`, `img`, `::-webkit-datetime-edit*`, `::placeholder`, etc.). In a typical SPA this is fine because the stylesheet only scopes the app's DOM, but **Obsidian loads every plugin's `styles.css` globally on the document**, so Preflight ends up resetting elements rendered by Obsidian itself **and** by every other installed plugin. Datepicker is one obvious casualty (the `::-webkit-datetime-edit*` rules zero out `padding-block`), but the same bug would silently degrade every plugin that exposes any input/select/list/heading.

## Fix

Skip the `base` layer entirely and import only `theme` + `utilities`:

```css
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
```

The `base` layer is still declared in the cascade order (so utility-layer overrides keep their precedence) but no rules are emitted into it.

### Why this is safe for our own UI

Every component class in `styles.src.css` (`.ge-controls__search-input`, `.ge-side-panel__close`, `.ge-zoom-controls__btn`, `.ge-controls__filter-btn`, …) already sets `border`, `background-color`, `color`, and `border-radius` explicitly. Nothing in the plugin relies on Preflight's `border: 0 solid` / `background-color: transparent` defaults for `<input>` / `<button>` / `<select>`. Verified by grepping for raw `createEl('input'|'button'|'select'|...)` sites — each one is paired with a class that sets the visual properties directly.

### Verification

- `bun run tsc` — clean.
- `bun run lint` — clean (0 warnings, `--max-warnings 0`).
- `bun test` — 85 pass, 0 fail.
- `bun run build` — clean.
- `grep` of generated `dist/styles.css`: zero hits on `^input`, `^button`, `^select`, `^ul,`, `^h1,`, `::-webkit-datetime-edit`, `::-webkit-calendar-picker-indicator`. The only `::placeholder` rule left is the plugin's own `.ge-controls__search-input::placeholder` (scoped, intentional).

## Related considerations

This is a generic Obsidian-plugin pitfall, not a Tailwind bug. Any Tailwind v4 plugin that ships `@import 'tailwindcss'` verbatim has the same issue. Worth flagging in `AGENTS.md` Tailwind section as a "do not do this" example next time that file is touched.
