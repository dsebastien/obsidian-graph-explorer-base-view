# 2026-06-17

## Security: clear "potentially vulnerable dependency" warnings (dev-only transitives)

### Context

The Obsidian community-catalog scan flagged a long list of "potentially vulnerable
dependency" warnings: `@conventional-changelog/git-client`, `tmp`, `lodash`,
`minimatch` (3.x/8.x/9.x), `ajv` (6.x/8.x), `flatted`, `handlebars`,
`brace-expansion` (1.x/2.x), `picomatch` (2.x/4.x), `yaml`, `fast-uri`.

**Key finding:** every flagged package is a **dev-only transitive dependency**. The
plugin's runtime `dependencies` are only `force-graph`, `immer`, `zod` — none appear
in the list. Nothing flagged is bundled into the shipped `main.js`, so the warnings do
not affect end users. They come from the build/release toolchain (eslint,
typescript-eslint, tailwind, commitlint, commitizen/cz-customizable,
conventional-changelog-cli). The reviewer still wants them cleared, so we pin patched
versions.

### Fix — `resolutions` in `package.json`

Added a `resolutions` block pinning each flagged package to a patched version. Used
Bun's yarn-style `resolutions` (not `overrides`) because **Bun does not support nested
`overrides`** and several packages need _per-parent_ versions:

- `ajv`: `eslint`/`@eslint/eslintrc` require v6 (`^6.14.0`) → **6.15.0**; commitlint &
  json-schema tooling require v8 → **8.20.0**. Scoped by parent so both majors coexist.
- `picomatch`: `micromatch@4` is built for v2 → **2.3.2** (scoped); `fdir`/`tinyglobby`
  need v4 → **4.0.4**.

Globally pinned (single major or API-stable): `@conventional-changelog/git-client`
2.7.0, `tmp` 0.2.7, `lodash` 4.18.1, `handlebars` 4.7.9, `flatted` 3.4.2, `yaml` 2.9.0,
`fast-uri` 3.1.2, `brace-expansion` 2.0.3, `minimatch` 9.0.9.

After this, the tree contains **no** version inside any flagged advisory range.

### Why `obsidian` and `zod` are also pinned in `resolutions`

Applying the scoped `ajv`/`picomatch` resolutions forces Bun to do a **full** graph
re-resolve (scoped resolutions are not applied incrementally). A full re-resolve floats:

- `obsidian: "latest"` → 1.13.1, which **removed the Bases-view option types the plugin
  imports** (`DropdownOption`, `TextOption`, `ToggleOption`, `ViewOption`) and changed
  `PluginSettingTab` — `bun run tsc` then fails. Pinned to **1.10.3** (the version the
  committed lockfile already used) to keep the build green. The plugin not yet compiling
  against obsidian ≥1.13 is a separate migration concern; lift the pin when that API is
  adopted.
- `zod` (runtime dep) → 4.4.3. Pinned to **4.1.13** so this security-only change leaves
  the shipped bundle byte-identical (no runtime change).

### Notes for next time

- Bun honors `resolutions` parent-scoped keys (`parent/child`) but **not** nested
  `overrides` — it warns and ignores them. Use `resolutions` for per-major splits.
- Scoped resolutions only take effect on a full re-resolve (`rm bun.lock && bun install`);
  an incremental `bun install` applies global resolutions but leaves already-locked scoped
  subtrees untouched. Pin any floating `"latest"`/runtime deps before the full resolve.
